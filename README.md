# MathFlow

MVP לכתיבת פתרונות מתמטיים בטלפון. דף רציף בעברית ובאנגלית, מקלדת מבנית, שמירה מקומית ונתיב הדפסה נפרד ל־A4.

## הרצה מהירה

נדרש Node.js 22 LTS ו־npm. אין שרת, חשבון, מפתח API או משתני סביבה.

```bash
npm ci
npm run dev
```

פתחו http://localhost:4173. לבדיקה בטלפון באותה רשת פתחו `http://<computer-IP>:4173`. חלק מיכולות המצלמה דורשות HTTPS או את מעטפת Android. לפריסה סטטית פרסמו את `dist/` לאחר:

```bash
npm test
npm run build
npm run preview
```

ה־ZIP כולל קוד מקור, lockfile, בדיקות, תיעוד, פרויקט Android ותוצאת build. אינו כולל node_modules. אין צורך בקובץ ה־prototype כדי להריץ.

## כתיבה

- הקלידו על הדף. הכיוון נקבע לפי הטקסט בכל פסקה; נוסחאות מבודדות תמיד ב־LTR.
- `∑ Math` מחליף למקלדת MathFlow בלי להזיז את סמן המסמך. כל תו מתמטי רגיל הוא יחידת עריכה בתוך אותה פסקה, באותו סגנון טקסט. אפשר לכתוב `a` ב־ABC, `x` ב־Math ו־`b` ב־ABC, למקם ביניהם סמן ולהוסיף עוד אות מכל מקלדת. Backspace עובד על תווים משני המקורות גם ברצף מעורב; נוסחאות עם שבר/חזקה/שורש נמחקות יחידה מבנית אחת בכל לחיצה.
- `⌨ ABC` מחזיר למקלדת המערכת באותו סמן. בתוך שבר, שורש, מעריך או אינדקס אפשר להמשיך להקליד אותיות וספרות באותו שדה; Backspace מוחק משם תו אחר תו. `∑ Math` מחזיר את המקלדת המתמטית להמשך ניווט עם NEXT. הקשה במקום אחר בדף מעבירה את הסמן לשם. הכפתור `שורה נפרדת` בכותרת המקלדת מוסיף/ממרכז נוסחת תצוגה.
- `x → NEXT → 2 → NEXT → 1 → NEXT` יוצר `x_1^2`. NEXT מדלג קודם בין מונה/מכנה ובין מבנים. בתוך מונה, השתמשו במקש החזקה אם רוצים חזקה לפני המעבר למכנה. כשאין עוד צעד מבני, NEXT מציג `שורה חדשה` ופותח פסקה חדשה כמו Enter, בלי לעבור למקלדת אחרת. גם בסוף נוסחה הוא משאיר את הנוסחה בשורה הקודמת וממשיך באותו מסמך.
- החלקה על כל שטח המקלדת: `→` לוגיקה, `←` מתמטיקה, `↑` מאגר סימנים. החלקה למטה על שטח המקלדת **לא עושה דבר**; `ABC` מעביר למקלדת הרגילה. ניווט *מבני* בנוסחה נעשה באמצעות NEXT, מקשי הסוגריים והמבנים, או `Alt+H/J/K/L` במקלדת פיזית.
- לכל מקש יש לכל היותר ארבע פעולות: הקשה רגילה, משיכה למטה, המשך שמאלה או המשך ימינה בלי להרים את האצבע. שלב המטה נדרש לפני פנייה לצד; תנועה אלכסונית אחת אינה בוחרת סימן צדדי. החלקה ישירה למעלה פותחת את מאגר הסימנים. חזרה קצרה למרכז מבטלת; מעבר ברור עד לצד השני בוחר את החלופה הנגדית. מקשים ללא חלופה צדדית אינם ממציאים פעולה.
- התו הכחול בפינה השמאלית הוא חלופה של קבוצות/לוגיקה; התו הירוק בפינה הימנית הוא חלופה של חישוב/אלגברה. שניהם גלויים עוד לפני המשיכה; החלופה התחתונה כתובה בראש המקש.

| מקש | הקשה | ↓ | ↓ ואז ← קבוצות/לוגיקה | ↓ ואז → חישוב/אלגברה |
| --- | --- | --- | --- | --- |
| `a/b` | שבר | `÷` | `∈` | `mod` |
| `·` | כפל בנקודה | `×` | `∩` | `⊗` |
| `+` | חיבור | `±` | `∪` | `⊕` |
| `−` | חיסור | `∓` | `∖` | — |
| `=` | שווה | `≠` | `⇔` | `≈` |
| `xⁿ` | חזקה | `1/x`: הבסיס הקודם נעשה מכנה | — | — |
| `(`, `)` | סוגריים רגילים | סוגריים מרובעים | — | — |

**אנימציית המשיכה:** לאחר כ־18px של תנועה מטה המקש תופס את המחווה, וכעבור 22px מופיעה בועה עם הסימן התחתון. תנועה רציפה לצד של כ־28px מחליפה את התו שבבועה בכחול או בירוק, בהתאם לסוג החלופה; גוף המקש נשאר ניטרלי. בחזרה למרכז הבועה נעלמת ומופיע ביטול; אם ממשיכים כ־28px לצד השני, הבועה חוזרת עם החלופה החדשה. שחרור מכניס את הסימן הנבחר ומחזיר את המקש באנימציה של 230ms. משיכה חזרה למעלה מבטלת עד לשחרור; הגדרת מערכת להפחתת תנועה מכבה אנימציות.
- סימני יחס כמו `=`, `≤`, `≥`, `∈` מקבלים רווח חזותי אחד מכל צד גם בלי מקש רווח. כפל, חיתוך ואיחוד מקבלים ריווח דק יותר; אחרי `∀` נוסף ריווח דק, בעוד `−` נשאר צמוד כדי לא לפגוע במינוס חד־מקומי. הריווח הוא חלק מתצוגת התו המתמטי בעורך וב־PDF, ולכן מחיקה אחת מסירה אותו יחד עם הסימן וה־LaTeX הנשמר אינו משתנה. נוסחאות מבניות ממשיכות לקבל את הריווח הטיפוגרפי של MathLive/KaTeX.
- סמל היישום הקודם מופיע ב־Android, בכותרת וב־favicon. מקשי המקלדת הוגדלו למגע באגודל. כפתורי מתמטיקה/לוגיקה הוסרו; החליקו ימינה ללוגיקה ושמאלה למתמטיקה.
- סימני יחס יוצאים ממעריך לא ריק או ממכנה מלא. `+` נשאר במעריך. אין ניחוש של כל ביטוי אפשרי.
- שורת סימנים אחת מעל המקשים משלבת הצעות לפי ההקשר עם קיצורים אישיים. גררו אותה אופקית כדי לראות את ההמשך; החלקה שמתחילה למטה על מקש נשארת מחוות סימן גם אם חוזרים למעלה או פונים הצידה. אין שורת קיצורים נוספת. ב־`כל הסימנים` אפשר להצמיד עד שישה קיצורים ולשמור את סדרם במכשיר.
- ההצעות מגיבות למיקום בסוגריים, שבר, מעריך, קשר לוגי או קבוצות. ההצעות משתנות לפי ההקשר והתרגיל, אך לוח הספרות והפעולות נשאר קבוע: ארבע שורות, ספרות 7–9 / 4–6 / 1–3 ו־0 בתחתית; סוגריים סמוכים, שבר ליד כפל, וחיבור וחיסור זה ליד זה. ABC, כל הסימנים ו־Undo/Redo נגישים בשורת הפעולות. מקשי הליבה בגובה 46px (44px במסך נמוך).
- `תרגיל` במשטח התחתון פותח הזנת נוסח שאלה בהדבקה/הקלדה או מתוך **מצלמה, גלריה וקבצים**. התמונה מוקטנת וזיהוי עברית/אנגלית מתבצע מקומית באמצעות Tesseract.js. בדקו ותקנו את הטקסט המזוהה לפני `שמירת תרגיל`: OCR עלול לטעות במיוחד בחזקות, שברים וסימנים דומים. התמונה עצמה אינה נשמרת בפרופיל התרגיל ואינה מוכנסת למסמך. אם לא זוהה טקסט, אפשר להקליד ידנית. תצוגה מקדימה מציגה נושא וסימנים שזוהו; רק שמירה מפורשת משנה עד שתי הצעות דינמיות לפי שלב הכתיבה. מקשי הליבה, ארבעת העוגנים ו־NEXT אינם משתנים. מתג `✓ תרגיל` מכבה/מפעיל התאמה; ההגדרה נשמרת עם המסמך, נכללת בביטול/שחזור ואינה מופיעה ב־PDF. אין כאן מודל AI פותר או שליחת התרגיל לרשת. שאלה ללא סימן מתאים אינה מפעילה התאמה; אפשר לתקן את הזיהוי או להוסיף מילה מפורשת.
- מתחת לטקסט התרגיל יש שורת **תיקון מהיר** שנגללת לצדדים. סמנו תו שזוהה לא נכון והקישו על הסימן הרצוי: `E`→`∈`, `R`→`ℝ`, `x2`→`x²`, וכן יחסים, כמתים וסימני חדו״א. אם אין בחירה, הסימן נוסף במיקום הסמן. כתיב אלגברי ברור כמו `x²+3x=0` או `f(x)=x^2` מזוהה גם בלי מילת מפתח; חשבון מספרי רגיל כגון `2+2=4` אינו משנה את המקלדת.
- צילום נסרק תחילה במלואו כדי לחסוך פעולה. אם יש בו גם פתרונות, כותרות או טקסט מיותר, לחצו `בחירת אזור`, גררו מסגרת על נוסח השאלה ולחצו `זיהוי האזור`. אפשר לגרור שוב, לבטל, לחזור ל־`תמונה מלאה` או לבצע `זיהוי מחדש`. בחירת האזור משנה רק את התמונה הזמנית לזיהוי; המסמך והתאמת המקלדת משתנים רק לאחר `שמירת תרגיל`.
- אחרי ביטוי חשבוני מספרי ו־`=` מופיעה בשורת ההצעות תוצאה בנגיעה אחת. למשל `2×(3+4)=` מציע `14`, ו־`1/3+1/6=` מציע `1/2` כשבר מתמטי. הקלדה בשילוב ABC ו־Math עובדת באותה פסקה. החישוב מקומי ומדויק עם שברים ומספרים עשרוניים; הוא מוגבל ל־`+ − × ÷ ^` ולסוגריים, לחזקות שלמות קטנות ולתוצאות קצרות שנכנסות למקש. אין הצעה לביטוי עם משתנה, שגיאה, חלוקה באפס או תוצאה לא חד־משמעית. ההכנסה היא צעד Undo אחד, והשבר נשמר כ־LaTeX ומופיע ב־PDF. התוצאה אינה נכתבת אוטומטית בלי לחיצה.
- `סימנים` מחליף את המקשים עצמם בלוח עם יותר מ־200 סימוני LaTeX: נפוצים, יחסים, יוונית, קבוצות ולוגיקה, חדו״א, פונקציות, חצים, גאומטריה ואותיות לטיניות. הקטגוריות נגללות בשורה אחת. בתוך מבנה מתמטי אפשר להקליד אותיות ב־ABC, והמאגר עדיין מספק סימונים מיוחדים. הקטגוריה האחרונה נשמרת בזמן העבודה, ובמצב לוגיקה הלוח נפתח בקבוצות אם לא בחרתם קטגוריה בעצמכם. חפשו בעברית, באנגלית או לפי הסמל. בחירה רגילה מחזירה מיד את המקשים; `רצף סימנים` משאיר את הלוח פתוח. לחיצה ארוכה על `x` פותחת אותיות.
- בזמן חיפוש בטלפון, מקלדת המערכת נפתחת ולוח הסימנים מצטמצם מעליה בתוך אזור המקלדת. בחירה בסימן סוגרת אותה ומחזירה את MathFlow. חיפוש אינו משנה את מיקום הסמן.
- כפתור `הקודם` מופיע לאחר מעבר מצב אוטומטי; הוא משאיר את ההחלטה שלכם עד שינוי סמנטי משמעותי.
- `□ תשובה סופית` הוא מתג בעל שלושה מצבים: כבוי → כל השורה → אלמנט → כבוי. במצב אלמנט נפתח סליידר צף ליד שורת הכתיבה. גרירת שתי הידיות משנה את תחילת הטווח ואת סופו מיד; כל צעד בציר שווה לאלמנט אחד וכל הציר מכסה את כל האלמנטים בשורה, ללא תלות ברוחב שלהם. מילים ומספרים הם יחידות שלמות; שבר/שורש/חזקה הם מבנים. בתוך מונה, מכנה או מעריך הסליידר פועל על אותה שורה פנימית. שורת כתיבה מסתיימת ב־Enter/Shift+Enter, ולא בשבירה חזותית לפי רוחב המסך. הסליידר הוא פס צף בלבד ללא כרטיס, כותרת או הוראות. הידיות דקות אך אזור המגע בגודל 44px; כשהן קרובות, הן נפרדות חזותית והניתוב נעשה לפי הקרבה לידית, בלי תלות בסדר הכפתורים. גרירה שלמה היא פעולת Undo אחת. המשך כתיבה או מעבר סמן סוגרים את הסליידר; כיבוי המתג מסיר את המסגרת. אפשר להשתמש גם בחצים/Home/End כשהידית ממוקדת. המסגרת נשמרת במסמך וב־PDF, והסליידר עצמו אינו חלק מהמסמך.
- כפתור תמונה: מצלמה, גלריה או קבצים. לחיצה על תמונה מאפשרת רוחב, יישור ומחיקה. תמונות מוקטנות עד 1600px ונשמרות כ־Blob ב־IndexedDB.
- דרך כפתור התמונות אפשר לבחור **גרף מפונקציה**. מזינים פונקציה של `x`, בוחרים טווח ציר `x` וטווח `y` אוטומטי או ידני, ורואים תצוגה מקדימה לפני ההכנסה לדף. נתמכות פעולות `+ - * / ^`, כפל סמוי כמו `2x`, סוגריים, `sqrt`, `abs`, `sin`, `cos`, `tan`, `exp`, `ln`, `log`, והקבועים `pi` ו־`e`. הפונקציה מפורשת מקומית בשפה מוגבלת ובטוחה; אין הרצת JavaScript ואין שליחת נתונים. תחומים לא מוגדרים נשברים לגרפים נפרדים כדי לא לחבר בטעות דרך אסימפטוטה. הגרף נכנס כתמונת PNG עצמאית, ולכן הוא נשמר, ניתן לשינוי גודל/יישור/מחיקה ומופיע ב־PDF.
- כפתורי `בטל` ו־`בצע שוב` צמודים וגלויים בשורה התחתונה של שתי המקלדות; הם מתעמעמים כשהפעולה אינה זמינה. גם Ctrl/Cmd+Z ו־Shift+Z פועלים. ב־Android נוספה שכבה native עבור Volume Down/Up.
- PDF פותח תצוגת A4 נפרדת. `הדפסה / שמירה` מפעיל את חלון ההדפסה; בחרו Save as PDF וכבו headers/footers של הדפדפן.

## Android

פרויקט Capacitor 7 מלא נמצא ב־`android/`; קוד כפתורי עוצמה והדפסה נמצא ב־`android/app/src/main/java/app/mathflow/mobile/`.

1. התקינו Android Studio, JDK **21**, Android SDK Platform **35**, Build Tools 35, Platform Tools. אפשר להשתמש ב־JDK המובנה של Android Studio אם הוא גרסה 21.
2. הריצו `npm ci` ואז `npm run cap:sync`.
3. הריצו `npx cap open android`, הגדירו Gradle JDK 21 וסנכרנו Gradle.
4. לחצו Run עם מכשיר USB/אמולטור. או, לאחר הגדרת SDK ב־Android Studio / `ANDROID_HOME`:

```bash
cd android
./gradlew assembleDebug
```

ב־Windows השתמשו `gradlew.bat assembleDebug`. APK צפוי: `android/app/build/outputs/apk/debug/app-debug.apk`.

אם הטלפון כבר מחובר ל־`adb` דרך Wi-Fi ב־Windows, אפשר להריץ משורש הפרויקט `scripts\run-on-phone.cmd`. הסקריפט מאתר את ה־SDK ו־JDK של Android Studio, כותב `android\local.properties`, בונה, מתקין את APK ה־debug ומפעיל את MathFlow. הוא עוצר עם הודעה אם `adb` אינו רואה מכשיר יחיד; ודאו תחילה ש־`adb devices` מציג `device`.

חבילות זיהוי הטקסט נכללות בפרויקט ונארזות בעת `npm run dev` או `npm run build`; אחרי `cap:sync` הן נטענות מהיישום גם ללא חיבור אינטרנט. ה־OCR מוסיף כ־26MB לנכסי היישום, והסריקה הראשונה עשויה לקחת כמה שניות במכשירים חלשים.

אם Gradle מדווח `SDK location not found`, פתחו את התיקייה `android/` ב־Android Studio כדי שיכתוב `android/local.properties`, או צרו את הקובץ עם הנתיב המלא ל־SDK, למשל `sdk.dir=C:/Users/<user>/AppData/Local/Android/Sdk`. אם daemon קורס, נסו מתוך `android/` את `gradlew.bat --stop` ואז `gradlew.bat assembleDebug --no-daemon --stacktrace`; ודאו ש־Gradle JDK מוגדר ל־21.

**לא נוצר APK בסביבת הפיתוח הזאת.** ניסיון Gradle נחסם ב־`Network is unreachable` בעת הורדת Gradle 8.11.1; בנוסף הסביבה כוללת JDK 17 ואין Android SDK. בוצע Capacitor sync בהצלחה, אך קוד Java לא קומפל ולא נבדק במכשיר. בנייה ראשונה זקוקה לרשת ל־Gradle, Google Maven ו־Maven Central. אין הבטחה ש־native volume, IME או print עברו בדיקת מכשיר עד השלמת הבדיקה הזו.

## שמירה ופרטיות

מסמך אחד נשמר אוטומטית במכשיר/פרופיל הדפדפן, ב־IndexedDB. נוסחאות כוללות LaTeX מפורש וגם עץ מבני עם מזהים יציבים. אין שמירת innerHTML כמקור לנוסחה. תמונות נשמרות בנפרד. סטטוס השמירה מוצג למעלה; שגיאת שמירה אינה מוחקת את הטקסט הפעיל.

הנתונים אינם מסתנכרנים בין טלפון למחשב או בין אתר ל־APK. ניקוי נתוני האתר מוחק אותם. ההיסטוריה חיה רק בסשן; reload משחזר את המסמך, לא את מחסנית undo. יציאה כפויה לפני כתיבה לדיסק עשויה לאבד את השינוי האחרון (debounce של 280ms). ממשק persistence מופרד להחלפה עתידית בשירות sync.

מדדי השימוש בתפריט הם מקומיים וזמניים בלבד, ללא תוכן נוסחאות או נוסח התרגיל וללא שידור. הם כוללים שימוש בהצעות תרגיל, מספר הקשות מתמטיות והפעלת/כיבוי ההתאמה, כדי להשוות בהמשך לכתיבה רגילה. היעד של 95% כתיבה ללא נגיעת סמן הוא יעד מוצר, **לא תוצאה שנמדדה**.

## ארכיטקטורה והחלטות

React 19 + TypeScript + Tiptap/ProseMirror לדף הרציף. מודל מתמטי עצמאי מפעיל את NEXT; MathLive משמש להקלדה מוצגת/typesetting, ולא רכיב math-field המנהל את הסמן. זוהי בחירה מכוונת: אין שימוש ב־private MathLive APIs ואין smartSuperscript המתחרה במכונת המצבים. המשתמש אינו נדרש להקליד LaTeX.

PDF נוצר מה־Document Model באמצעות KaTeX ו־HTML/CSS נפרדים. אין העתקה של DOM העורך, סמן או selection. כל הפונטים המתמטיים נכללים ב־build. ראו [ARCHITECTURE](docs/ARCHITECTURE.md).

קובץ `mathflow-prototype-0.9.zip` נותח כרפרנס. התנהגות הכפתורים והמחוות נשמרה ברעיון; הוחלפו state זמני, ניווט לפי fallback ו־innerHTML persistence. לא נדרשת תאימות למאגר הנתונים הישן.

## אימות ומגבלות

150 בדיקות אוטומטיות ו־TypeScript build עברו בגרסה זו. נבדקו במודל הקלדה ממקלדת המערכת במונה ובמכנה, Backspace, שמירת LaTeX, מחוות, תווי עברית, היעדר placeholders, בחירת תשובה ו־PDF. נוספו בדיקות חישוב מדויק, קריאת מסמך מעורב, סוף מחזור NEXT, ירידת שורה וביטול פעולה, וכן התאמת תרגיל ושמירה. בדיקת עשן מקומית טענה מודלים של עברית/אנגלית וזיהתה טקסט מתוך PNG; נבדקו גם נתיבי השרת של worker, מודל WASM וקובץ שפה. בגרסאות הקודמות בוצעה כתיבה אמיתית בדפדפן, כולל עברית, מחזור scripts, מחוות, mode back, מסגרות, עיצוב, תמונות, גרף, reload ו־PDF preview. צילום תרגיל והכפתורים החדשים עדיין דורשים בדיקת מגע פיזית; אין טענה ל־QA במכשיר. פירוט: [QA_MATRIX](docs/QA_MATRIX.md).

זה MVP פונקציונלי, לא אישור מלא של Definition of Done במכשיר Android. עוד נדרשים בדיקת IME אמיתית בתוך שבר, מגע באגודל ולחיצה ארוכה לסימון, Volume keys, צילום תרגיל והשלמת Save as PDF במערכת. בדיקות הדפדפן ברוחב טלפון אינן אמולציית Android. שבר, חזקה ושורש נשארים מבנה פנימי אחד עם סמן מבני; קלט ה־IME נשמר כתווי LaTeX מפורשים במקום הפעיל. אין importer של LaTeX שרירותי, matrix, מסמכים מרובים או cloud sync. ה־OCR מזהה טקסט עברי/אנגלי ומחייב תיקון אנושי של מתמטיקה מורכבת; אינו מפענח מבנים מתמטיים ל־LaTeX. סימון מתמטי חלקי מוגבל לרצף מבני אחד. ביטויים ארוכים במיוחד אינם נשברים אוטומטית לשורות ועלולים לחרוג מרוחב הדפסת A4. אין pagination חי בעורך; הדפדפן מחלק עמודים בהדפסה. תמונות שנמחקו עשויות להישאר ב־asset store כדי לאפשר undo; אין garbage collection ב־MVP.

הבדיקה החשובה הבאה: כתבו בטלפון פתרון בעברית עם שבר, חזקה ואינדקס, עברו ל־ABC וחזרה והשלימו באמצעות NEXT והחלקות — ספרו כמה פעמים נדרשה נגיעה ידנית בסמן.
